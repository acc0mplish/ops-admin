# 云费用 FinOps 优化方案

更新时间：2026-07-17  
范围：`backend/*finops*`、`web/src/views/integration/finops/*`、对应 API。本文不涉及无关模块。

## 1. 现状评估

| 能力 | 当前实现 | 结论 |
| --- | --- | --- |
| 云账号 | 可维护 AWS、Azure、GCP、阿里云、腾讯云和自定义账号；凭据不在接口返回 | 阿里云、腾讯云已有内置账单拉取；AWS/Azure/GCP 目前通过自定义账单适配接口接入，不能误标为内置官方同步。 |
| 账单同步 | 默认同步含当前月的最近 6 个自然月；逐月执行、失败隔离、按外部 ID upsert、保留月度执行日志 | 已满足核心同步规则；需要在页面选择账期范围、明确月度总账单按日均摊的估算口径。 |
| 费用看板 | 可展示 3/6/12 月趋势、云厂商分布、累计/本月/上月/环比/最近同步时间 | 缺少账号过滤、账单数据质量提示、统一的后端汇总指标。 |
| 费用拆分 | 单个自然月、按产品/地域和费用明细 | 后端具备账号、标签、资源维度，页面未完整暴露；明细应标明“精确日账单/估算日账单”。 |
| 资源拆分 | 必须选账号和日期；支持地域、资源类型筛选 | 聚合键仅使用资源 ID，存在不同账号相同资源 ID 被合并的风险。 |
| 优化建议 | 支持默认策略、选择 AI 模型、HTML 报告、PDF 打印、删除 | 默认/AI 策略已覆盖空闲资源、低利用率、计费方式、闲置基础资源和节省额；缺少账号/账期分析范围，且没有运行指标时只能标记为“待核查”，不能把推断当成事实。 |
| 同步历史 | 有同步状态、记录数、金额、账期、耗时和错误信息 | 已修复前后端字段不一致；需让同步结果在触发后逐月可见。 |

## 2. 数据口径与边界

1. 最近 6 个月始终指“包含当前月的最近 6 个自然月”。
2. 同步按自然月逐月运行；一个月失败不影响其他月份。
3. 当前月允许不完整，所有页面需明确“截至当前”。
4. 阿里云当前采用一次月度实例账单拉取，再在本地按当月有效天数均摊为日统计，避免对每一天调用云 API 导致超时。此类记录必须以 `daily_estimate` 标识展示，不能与云厂商精确日账单混淆。
5. 没有资源运行指标（CPU、内存、IOPS、连接数）时，优化建议只能是核查建议，不能断言资源空闲或低利用率。

## 3. 实施计划

### P0：本次实施

1. **账号能力透明化**
   - API 返回账单接入能力：阿里云/腾讯云为内置 API，AWS/Azure/GCP/自定义为适配器模式。
   - 页面明确展示能力和配置提示，避免造成“所有云厂商已内置同步”的误解。

2. **看板和拆分口径完善**
   - 看板支持云账号过滤，后端一次返回本月、上月、估算日账单条数、最近同步时间等指标。
   - 费用拆分保留产品、地域、按日明细；增加高级维度（账号、标签、资源）并显示数据质量标识。

3. **资源拆分正确性**
   - 用 `账号 + 资源 ID/名称 + 资源类型` 作为聚合键，阻止跨账号误合并。
   - 保持账号、日期范围必选及地域、资源类型多选筛选。

4. **同步可控性和可观察性**
   - 同步页提供“最近 3/6/12 个月”范围选择，并显示本次逐月结果。
   - 执行历史展示账号、厂商、触发方式、账期、记录数、金额、耗时、开始/完成时间和错误原因。

5. **建议生成范围**
   - 生成建议允许选择云账号和分析账期；默认策略与 AI 策略使用同一套 FinOps 分类框架。
   - 报告显示分析范围与“账单推断/待核查”说明。

### P1：后续迭代

1. 接入 AWS Cost Explorer、Azure Cost Management、GCP Billing Export 的官方适配器，并以 IAM/服务主体/OAuth 授权模型分别建模。
2. 接入资源监控数据，给低利用率与空闲资源建议增加可验证证据（时间窗、阈值、指标值）。
3. 引入预算、异常检测、成本归属规则（业务单元/项目/环境）和预算告警闭环。
4. 对云凭据实施 KMS/信封加密、轮换记录和最小权限检测；当前数据库中的凭据字段不应被视为已完成加密方案。

## 4. 接口约定

| API | 本次约定 |
| --- | --- |
| `GET /api/v1/integration/finops/dashboard` | 支持 `start`、`end`、`account_id`；返回汇总指标、月趋势、厂商分布、数据质量统计。 |
| `GET /api/v1/integration/finops/breakdown` | 必传 `month=YYYY-MM`；支持 `account_id` 与 `dimension=service/region/account/tag/resource/detail`。 |
| `GET /api/v1/integration/finops/resource/list` | 必传账号与起止日期；支持多选 `region`、`resource_type`。 |
| `POST /api/v1/integration/finops/sync/trigger` | `accountId` 必传；可选 `start_month`、`end_month`，省略时为最近 6 个自然月。 |
| `POST /api/v1/integration/finops/recommendation/generate` | 支持 `strategy`、`modelId`、`account_id`、`month`；不配置 AI 或选择默认策略时走内置规则。 |

## 5. 验收标准

- 费用看板可切换 3/6/12 月和账号，趋势连续补 0，当前月标识“截至当前”。
- 费用拆分仅统计选中自然月；产品、地域、账号、标签、资源及日明细口径一致。
- 日均摊数据有明确“估算”标识；不存在伪造“精确日账单”的展示。
- 资源拆分在账号、时间范围未选择时不发起数据查询；不同账号的同名/同 ID 资源不会合并。
- 同步页面能选择范围并返回每月成功/失败、数量、金额、错误；历史字段完整。
- 优化报告展示分析账号、账期、策略、数据限制以及五类 FinOps 策略；建议可查看、打印 PDF、删除。
- 后端测试、前端构建通过；实际临时启动前后端验证后自动关闭。
