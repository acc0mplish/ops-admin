# OPS Admin 按应用局部设计规范

## 目的与边界

本规范用于指导现有 Vue 页面逐页优化。目标是专业、现代、克制且高信息密度的 OPS/SRE 平台；保留现有路由、接口、权限与交互，不新增业务流程。

所有应用共用基础语言：`#18243A` 主文字、`#66758D` 次级文字、`#E3E8F0` 边界、`#F5F7FB` 页面底色、12px 内容卡片圆角、7px 控件圆角。每个应用只在“当前态、关键指标、风险等级”使用本应用色，避免整页高饱和。

## 1. 控制台

**页面范围**：仪表盘、业务拓扑、用户/角色/菜单/部门/岗位、系统设置、登录日志、操作日志、个人信息。

**局部方向**：强调“管理入口”和“系统可控性”。仪表盘采用一条低饱和深蓝状态横幅 + 四项关键 KPI；管理列表采用标题、过滤工具条、数据表三段式；审计日志使用数量、风险、时间作为优先扫描信息。

**页面规则**：

- 系统管理列表的新增操作固定在标题区右侧；查询、同步等辅助操作置于浅灰筛选面板。
- 角色、菜单、部门树表中，层级使用缩进、细分隔与图标，不使用大面积色块。
- 日志页的成功、警告、失败只使用状态标签和左侧细色条；详情使用 Drawer，保留表格上下文。
- 系统设置使用分段 Tabs + 两列配置区；预览仅服务于配置结果，不应抢占表单视觉权重。

## 2. 资产管理

**页面范围**：资产概览、环境模型、终端登录、主机/主机组/凭据/云账号、数据库、网关、数据库详情与工具页。

**局部方向**：强调“资源状态”和“可操作性”。资产概览优先显示在线、认证、连接、资料完整度；资源列表优先显示名称、地址、环境、状态和最近更新时间。

**页面规则**：

- 概览页首屏由资源 KPI、关键资源入口、健康提醒组成；健康提醒只展示异常或待处理项。
- 主机、数据库、网关列表将在线/连接状态置于名称右侧或独立状态列；地址、标签等次级信息弱化显示。
- 凭据、云账号等敏感资源的操作区使用“查看 / 编辑 / 更多”，危险操作收进更多菜单并保持风险确认。
- 终端、DBMS、导入与备份页采用工具台布局：固定标题与上下文、明确编辑区、可折叠辅助区、稳定的底部操作区。

## 3. 容器管理

**页面范围**：服务管理、服务资源拓扑、服务详情/日志/健康诊断、K8s 集群、节点、命名空间、工作负载、Pod、网络、配置存储与终端。

**局部方向**：强调“集群上下文”和“运行态判断”。所有页面在标题附近持续显示集群、命名空间和资源类型，避免用户在深层页面失去上下文。

**页面规则**：

- K8s 页面统一为 Cluster context bar → 二级资源 Tabs → 筛选工具条 → 数据区。
- 工作负载和 Pod 表格首列使用名称 + 命名空间/镜像等摘要；Ready、重启次数、年龄、状态为高优先级列。
- YAML、日志、终端等深色工作区只使用在内容编辑/输出区域；周边导航、筛选和操作保持浅色。
- 资源拓扑以健康状态、服务关系和可点击详情为核心；连线和装饰不超过信息本身的视觉权重。

## 4. 标准运维

**页面范围**：脚本库、命令执行、脚本执行、文件分发、执行历史、定时任务、作业编排、作业列表、人工确认、作业历史与模板。

**局部方向**：强调“操作前确认、执行中可观测、执行后可追溯”。表单不做营销式大卡片，风险和执行范围比装饰更重要。

**页面规则**：

- 命令、脚本、文件分发采用任务信息 → 目标范围 → 执行参数 → 风险提示 → 主操作的顺序。
- 命令编辑器使用等宽字体和轻量行号；仅编辑器为深色，页面其余区域保持浅色。
- 执行历史、任务日志和作业历史将状态、目标数量、开始时间、耗时、失败数做成可横向扫描的摘要。
- 作业编排画布采用中性画布；节点用类型色小面积识别，选中、错误、等待人工确认必须有明显且不冲突的状态。

## 5. 应用中心

**页面范围**：项目列表、应用拓扑、构建任务、构建历史、镜像仓库、CI/CD 流水线。

**局部方向**：强调“交付链路”。项目、构建、镜像、流水线应让用户一眼看到环境、版本、状态与下一步操作。

**页面规则**：

- 项目和构建任务页使用标题操作区、筛选区、结果表三层结构；仓库地址和分支使用等宽次级文字。
- 构建历史使用阶段时间线，成功/进行中/失败状态保持一致色义；日志 Drawer 或 Dialog 使用深色仅限日志正文。
- 镜像仓库用卡片列表呈现连接状态和地址，凭据内容默认遮蔽。
- 流水线编辑页将模板选择、阶段编排、阶段配置、运行详情明确分区；发布与人工确认节点使用风险提示。

## 6. 消息通知

**页面范围**：消息模板、通知媒介、通知规则、发送日志。

**局部方向**：强调“消息能否准确送达”。主视觉应服务于通道、路由、失败原因和发送时间。

**页面规则**：

- 模板页采用编辑/预览双栏；预览模拟对应渠道的真实信息密度，不使用无意义设备框。
- 通知规则以“事件 → 模板 → 媒介”的路由链展示，当前启用状态清晰可见。
- 发送日志的结果、响应码、耗时、失败原因需在首屏可扫读；详细请求/响应收纳在详情面板。

## 7. 集成中心

**页面范围**：导航管理、公开导航、AI 对话/会话/模型/工具/知识库、FinOps 看板/账号/拆分/建议/资源/同步。

**局部方向**：这是配置与分析混合区域。导航管理强调入口组织；AI 强调会话与工具边界；FinOps 强调金额、趋势和可节省金额。

**页面规则**：

- 导航管理以分组侧栏 + 入口卡片工作区呈现，入口卡片只使用图标、名称、地址摘要和状态。
- AI 对话使用清晰的会话栏、消息阅读区和固定输入区；工具调用、思考中、失败状态以紧凑状态块显示。
- 模型、工具与知识库为配置型页面，采用表格/编辑器结构，连接状态和默认配置可见。
- FinOps 页面中的金额采用等宽数字、账期和同比说明；趋势与拆分图表须具备图例、空态和筛选上下文。

## 8. 监控中心

**页面范围**：监控概览、智能大屏、数据源、即时查询、日志、链路、告警规则/事件/屏蔽/聚合、监控大屏、巡检大屏。

**局部方向**：强调“风险优先”和“快速定位”。当前风险、责任人、持续时间、影响范围必须比趋势装饰更突出。

**页面规则**：

- 监控概览首屏固定为当前风险、监控质量、趋势、最近事件；异常优先，健康状态降噪展示。
- 数据源、规则、告警事件使用状态列、最近更新时间、负责人和快捷操作；批量操作放在独立工具条。
- PromQL、日志、Trace 页面采用查询区、结果区、详情区的工作台布局；查询历史和字段面板可收缩。
- 驾驶舱与大屏以实时信息为先，不复用普通列表页大边距；但仍保持明确标题、刷新状态、时间范围和告警入口。

## 逐页验收清单

每个页面实施后都应在浏览器中检查：

1. 标题、说明、主操作和筛选区是否能在首屏快速定位。
2. 表格/卡片是否具备统一边界、行高、空态、加载态与状态色义。
3. Dialog、Drawer、日志/终端工具区是否保持清晰焦点与可关闭路径。
4. 当前应用、菜单层级、面包屑和标签页是否持续提供位置感。
5. 1366px 桌面视口下是否无非必要横向滚动，且信息密度符合运维场景。
